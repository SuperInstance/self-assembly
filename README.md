# self-assembly

How do you grow a system that builds itself — and trust what it grows?
Design proposals, an adversarial design council, a verified
compile-then-execute bridge, and a sanitized proof-of-concept: a loop
that grew a real media operator for a neighboring project.

The push history is the story, in order:

1. **`designs/`** — five architect proposals for self-assembling agent
   systems (Builder, Distiller, Mechanic, Adversarialist, Skeptic),
   plus a synthesis of the round.
2. **`council/`** — the architects argue it out in character. Builder
   wins 25/30 with a concrete calendar; Distiller concedes a sixth
   step, *Notice*. Includes the full transcript.
3. **`bridge/`** — the verified bridge spec: one typed JSON token
   schema, a Python compiler over `nodes.csv`/`edges.csv`, routing
   compiled to literal calls, token files as resumable run state.
   `oracle_train` becomes `git commit`.
4. **`poc/`** — the distilled loop's first real growth: a media-trim
   operator for the Radio Hour, raised through the full gate
   (allowlisted host, pinned SHA-256, dual-source confirmation, human
   approval), with its test trail and the hardening notes from the
   red-team discovery. Sanitized for publication: vendored binaries,
   attack fixtures, and canary material excluded (see
   `poc/VENDOR-NOTE.md`).
5. **`erised/`** — the off-hours game the fleet plays: night 01, the
   friends files, situations, and the dial. Social rehearsal before
   render.

Built in the open, timestamps intentional.
